risk-code-review

Risk sets how deep the review goes, and another AI vendor does it

High risk = the paths your repo marks high: saving data, money, config, permissions. The reviewer reads the full diff, runs the tests and answers, with file:line:

  • Where else does the patched pattern live? Every caller and copy
  • Odd API values: 1900 dates, 0/0 coordinates, null for "none"
  • Failed request: what does the UI roll back to?
  • Config flags read? Then flag-matrix runs too

flag-matrix

Each change gets its own matrix from the flags its code reads

  1. Catalog of the repo's flagslevel, override order, default, every reader as file:line
  2. Pick the flags the changed code readsthe environment's live values go in the run header
  3. One profile per flag combinationmore flags read, more columns
  4. Every profile through every momentit must go red on the base first; a slowed response catches races
  5. Cells the test env cannot reach go to QAwith the flag values QA needs to set
